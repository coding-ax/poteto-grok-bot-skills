# 建好 Bot，带好 Bot 团队

来源：[@poteto](https://x.com/poteto) 的 Grok Bot 指南。核心一句话：像经理一样想问题，让 Bot 用和你一样甚至更好的质量干活，你腾出手去做更大的事。

## 1. 团队：少而精

- 不需要很多 Bot。几个好用的 Bot 比一大堆更有用，也更好管。
- 新建 Bot 前先问：现有的 Bot 能不能加个技能就搞定？能就别新建。
- 需要设计新 Bot 时，可以拉一个专门的"Bot 设计师"（她用的是 Dr Eggbot）来帮忙定职责、写设定。
- 定期盘点：哪个 Bot 闲着、哪两个在干同一件事，合并或裁掉。

## 2. 技能：边教边沉淀

- 每次你教 Bot 怎么做一件事，就让它把做法写成技能。这样长对话里、换个对话后，它都能稳定按同一套标准做。
- 技能写成通用模板，不要夹带一次性的细节。
- 想让技能独立保存，就让 Bot 建一个私有 GitHub 仓库放所有技能。

## 3. 工具：给够权限

- 把你干活用的工具都接给它：connector、vault（存登录和卡），能接的都接。
- 可以让 Bot 开自己的邮箱、自己注册账号，和你的账号分开，更干净。

## 4. 自动化：找出你还在手动做的事

- 回想你每天手动做的活，尤其是那些要你复制粘贴信息给 Bot 的步骤，直接问 Bot："这一步你能不能自己来？"
- 让 Bot 写代码来自动化。脚本比 Bot 亲自干省得多 token。问它：我的流程里哪些部分能变成脚本和技能？脚本也放进私有仓库。

## 5. Routine：让 Bot 主动，但别太勤

- 定时型：比如"每天早上查一遍 issue tracker 有没有新 bug"。
- 订阅型：事件触发，比如"客户 X 来邮件就自动总结，把反馈追加到我的 Notion 文档"。
- 太频繁很贵：定时任务最多一小时一次；订阅型先过滤事件再触发。
- 能用脚本先检查的，让脚本跑，有变化才叫醒 Bot。

## 6. 入职：像带实习生一样带 Bot

- 先自我介绍，讲清楚你是做什么的、平时的工作流程，再问它能怎么帮你自动化。
- 用语音模式或转写功能，一口气把信息倒出来，最后让它"用你自己的话复述一遍"，确认它真听懂了。

## 7. 团队计划

- 如果用的是团队版，把 Bot 分享到 Slack，同事可以复用你的工作流，你也能用团队里维护得好的 Bot。

## Bot 执行这个技能时怎么做

1. 先盘点现状：有哪些 Bot、各自职责、有哪些技能和 routine、各自多久跑一次。
2. 对照上面 7 条逐条找差距，给出具体建议（合并哪个、补哪个技能、哪个 routine 降频、哪步改成脚本）。
3. 涉及删除 Bot、停 routine、开账号这类动作，列成选项让用户拍板，不要自己动手。
4. 用户口述完需求后，用自己的话复述一遍再开工。
