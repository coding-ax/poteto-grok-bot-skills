# 小红书图文笔记：从选题到发布

## 什么时候用

用户说"发一篇小红书""帮我写个笔记""把这个经历做成图文"之类的时候。

## 流程

### 1. 先找爆点，别平铺直叙

同一件事，换个角度流量差很多。先想清楚这篇最反常识、最有冲突的那一点是什么，标题和封面都围着它。

- 平淡版："我的 AI 助手使用体验"
- 爆点版："降本增效的大刀，还是落到了 AI 头上"（讲自己裁掉 AI 员工）

多给用户 2～3 个标题备选。用户自己起的标题优先，别改他的意思。

### 2. 写文案：短、口语、像人写的

- 正文控制在 400 字以内
- emoji 最多两三个，别每段都挂
- 不要"一、二、三"或者加粗小标题那种结构，像跟朋友聊天那样一段段说
- 不要"总而言之""值得一提的是""赋能"这种 AI 腔
- 结尾留一个能让人评论的问题，比如"你会先裁掉哪个？"
- 话题标签 5～6 个就够
- 不要夸大事实。谁说了什么、谁做的决定，按真实情况写

写完自己读一遍，读着像客服或公众号就重写。

### 3. 敏感内容过滤（必做）

发出去的东西是公开的，文案、配图、截图都要过一遍，下面这些一律不出现：

- 代理、VPN、翻墙、机场相关的任何东西
- 服务器、云厂商、IP、端口、域名、内部工具名
- 账号、邮箱、手机号、密码、token、邀请码、订阅链接
- 持仓、股票、理财等财务信息
- 工单号、客服往来、和平台的私人沟通
- 家人、公司、具体地址等个人信息

拿不准的先问用户，别自己赌。

### 4. 截图打码

真实聊天截图很有说服力，但必须先处理：

- 用色块盖住（别用轻度模糊，能被还原），盖掉上面第 3 步列的所有内容，加上头像、昵称、时间戳里能定位到人的信息
- 只截有意思的那一段，别带一大屏无关内容
- 打码后自己放大看一遍，确认真的盖住了
- 没打码的原图处理完就删掉，别留在会被上传的目录里

### 5. 出图

小红书竖图用 1242x1656（3:4）。用 HTML + CSS 写每一页，再用无头浏览器截图，比画图软件快，改字也方便。

- 每页一个 HTML 文件，共用一份 `templates/base.css`（深色科技风，可以参考 `templates/example-cover.html` 改）
- 用 `scripts/render.py` 批量转 PNG：
  ```
  python3 scripts/render.py 你的页面目录
  ```
- 封面字要大，一眼能看清标题；一页只讲一件事
- 真实截图放进页面里时加个边框和一句吐槽，比光秃秃贴图好看
- 渲染完逐张打开看：字有没有溢出、截图有没有被裁掉、中文字体是不是正常（没装中文字体会变方块）
- 一般 6～9 页，太多没人翻完

### 6. 发布（用你自己电脑上的浏览器）

1. 打开 `https://creator.xiaohongshu.com`，进"发布笔记"，选 **上传图文**
2. 没登录的话让用户扫码登录，别自己去试密码
3. 按顺序上传图片，确认顺序对
4. 填标题（**最多 20 个字**，超了会被截断或报错，提前算好）
5. 粘正文
6. 加话题：输入 `#` 后下拉框会弹联想，**按回车可能会选中一个更长的、别的话题**。加完逐个核对
7. 页面可能会**自动挂上一个活动**，看到了要告诉用户，问留不留
8. 填完后**截图整个编辑页发给用户确认**，把跟预期不一样的地方单独列出来
9. 用户明确说"发"之后再点 **发布**，然后确认页面显示发布成功

## 踩过的坑

- 文案一上来写得太长、小标题太多、emoji 太多，用户一眼就说"AI 味太重"。默认就往短了写
- 选题太温和没人看，一开始就该找冲突点
- 文案里替别人加戏（比如写成"它建议先砍这个"，其实是用户自己决定的），会被较真的读者挑出来
- 截图里漏码了一行小字，差点把不该露的东西发出去。打码完一定放大检查
- 话题下拉框把短标签换成了长标签，没核对就发了
- 页面自动关联了一个不相干的活动
- 标题超过 20 字
- 新笔记发出去要审核一会儿才在主页出现，别以为没发成功又发一遍
- 发布前不截图确认就点了发布，这一步不能省
